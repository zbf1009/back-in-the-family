Audited 2026-11-04 against the tree at commit `72b8abb` (plus the docs changed in this task). Every row was checked by running a command, reading the code or reading the test; "kiro-log" means the entry in `docs/kiro-log.md` for the named task, which I read but did not re-run unless the evidence column says so. ## Gaps and deviations

1. **R11.1-R11.3, hooks end to end.** The hook triggers were observed to fire (edit-tool saves; `PostTaskExec` on `task_update` completions), and both scripts catch their injected faults when run by hand. No agent has ever seen a failing hook's output, so "report to the agent" and "shown to catch" are unproven. Manual edits were never tested. Not upgraded to `met`.
2. **R10.1.** The weekly measurement exists only as the numbers at commit `bac46e3`; the code no longer supports weekly ticks. Re-running the comparison means checking out that commit.
3. **R7.3.** The 25 MiB check is a gate script step, not a test, and it does not look at the raw release `.wasm`.
4. **R8.1.** Thread coverage is `thread::spawn` only.
5. **R8.2.** Hook injections are script-half only; the exhaustiveness guards (Canon, `testing.rs`) had no logged injection until task 13; later gates (size check, version check, `bench` steps) had none either, except the two shown by hand in task 13. kiro-log task 7 refers to a Canon-guard demonstration "in task 5/6" that I could not find in those entries.
6. **R5.3.** Satisfied only vacuously: there is no derived state to exclude. Rule 10 (rebuild after load) is out of scope for this spec.
7. **R4.4.** The `IdExhausted` rejection has no end-to-end test (2^64 ids are unreachable); only the counter and the checksum-sensitivity mutation cover it.
8. **R3.1 wording.** The requirement names three hash inputs; `draw` takes five (seed, entity, tag, tick, index) by design decision D2. Counted as met.
9. **R1.2.** The simulation's test graph contains `rand` (through `proptest`, dev-dependency only). `gates.sh` checks the `normal` tree only, which is the intended scope.
10. **Unverified log claims.** Hook marker-file observations from task 10 (temporary marker lines, later removed) and the manual-edit / sub-agent behavior cannot be re-checked. Also unexplained: the task 11 checkbox changing to `[x]` without a `task_update` call (kiro-log task 11); the second `PostTaskExec` marker line is of unknown origin.
11. **Test coverage on wasm32.** Only the sim-wasm tests run on wasm32; sim-core's unit tests, including the pinned `draw` values, run natively only.
12. **Hook scripts run release builds** (`hook-replay.sh`), so overflow checks and `debug_assert!` are off in that run. `gates.sh` runs them in debug.
