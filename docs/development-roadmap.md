The public rules site makes **zero model calls**. See [accounting boundary](../.kiro/specs/judge-demo-release/design.md#L121).

## Proposed next plan and Spec questions

**Spec-side recommendation, not a new Author decision:** submit the execution-complete public delivery for final Spec acceptance → plan B including existing Bribe/Haunting entries and existing path/customization usability → plan presentation text → individually justified thickening. Tasks 10.1–10.4 are already execution-complete, not future implementation work; final acceptance remains pending. Only **slow-think → B → text** is the already-selected successor order. New conflict, economy and broader customization belong to separate gameplay expansion; their priority may change when a concrete pacing/playability issue blocks the core loop. There are **no date commitments** or B/text implementation grants here.

Before drafting the next real Spec, decide:

1. **B:** which facts lead (current body/soul, who remembers me, stakes and consequences); scene/life versus optional map; viewport behavior with long names and many slots; reachable actions/scrolling; which trial assets to formally adopt and which gaps to draw.
2. **Backlog ownership:** assign every selected debt to a target Spec or an explicit revisit trigger, rather than indefinite “later.” Keep existing-mechanism UI completion distinct from new conflict/economy/customization rules; prioritize genuine loop blockers when demonstrated.
3. **Text:** exact rule-fact contract and evidence references, request triggers/context bounds, model/service choice, allowance/failure behavior, payload identity/storage/replay, and measurable factual/tone quality. No rules/checksum changes or replay re-requests.
4. **Gameplay thickening:** choose a small, specific gain in meaningful choices, pace or consequences before expanding mechanics; do not infer a fixed expansion queue from this archive.
