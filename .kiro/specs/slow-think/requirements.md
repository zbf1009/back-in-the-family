# Requirements Document

## Introduction

Spec 7, `slow-think`, adds the production decision bridge promised by the steering documents. The rules-only first-playable slice remains the complete fallback. When the browser is connected to the deployable Worker and the request budget permits it, Workers AI `@cf/cloudflare/clef` may choose inside the existing closed option set for an eligible underworld Decision_Node. The simulation still owns the facts, Frozen_Context, legal options, effects, Rules_Default and replay state.

The spec also makes the site deployable as one self-contained Workers application: static assets, the prebuilt WASM, a Worker module and a Wrangler configuration. The source repository remains the place where gates and builds run. A generated artifact branch is the input to the Deploy to Cloudflare button; no built artifact is committed to `main`.

The spec does not add structured fact synthesis, generated presentation text, a new gameplay family, or the B-direction UI redesign. It does not make the model authoritative. A model result is advisory until it passes the same closed-set validation at the browser boundary and is recorded as an input.

### Existing contracts this spec consumes

- `sim-core::Sim::preview_node(payload)` clones the current World, applies already submitted inputs for the current tick, and returns a `NodeSpec` with the frozen context, predicted trigger sequence, options and Rules_Default without changing the run. Its clone may recompute deterministic keyed RNG values needed for an exact Rules_Default; it SHALL not consume the live run's random state, sequence, input stream or checksum.
- A same-tick underworld decision is represented by two inputs in order: the trigger (`Dream` or `Bribe`) and `Choose { node: Trigger { seq }, option }`. `try_submit_all` validates and queues the batch atomically; resolution then happens in the existing same-tick node step.
- `sim-core::llm::system_one::render_system_one` renders the existing System One mapping, and `llm::validate::validate_raw_choice` validates an exact option ID against the closed options. These functions are pure and do not call a model; Spec 7 SHALL reuse them without editing the R14.4-pinned `sim-core/src/llm` files.
- Replay format 5 already records `Choose` as an ordinary input. An optional model fingerprint may be added to that input without changing the World checksum when the applied option and `ChoiceSource` are otherwise unchanged, or invalidating existing no-fingerprint replay records.

### Author decisions already in force

- One Workers AI request per eligible Decision_Node; no retry.
- The default model is `@cf/cloudflare/clef`, using the System One mapping and the `choice` question.
- The browser waits up to 10 seconds. Timeout, runtime error, invalid output, confirmed platform quota exhaustion and a session cap all use Rules_Default; rate limiting is reported separately from daily-quota exhaustion.
- The page permits 40 model requests per session by default; the deployer may configure the limit. This is not a public-endpoint abuse barrier. No application-level per-minute limiter and no application-owned daily counter are added.
- The shared Cloudflare account's quota is an external platform fact. A daily-quota notice is shown only for a confirmed quota signal; missing usage or an unclassified 429 is reported as unknown/rate-limited rather than asserted to be quota exhaustion.
- Accepted requests target approximately 50 neurons or less as an observation target, not a byte/token conversion contract. The actual in-game request bytes, input tokens and provider usage must be measured before a hard request-size limit is chosen; neurons are reported only when the provider supplies them or explicitly documented as an estimate.
- Synthesis is rules-only. In-browser WebLLM and transformers.js are not used. Presentation text remains a later spec.
- The Deploy to Cloudflare button uses a CI-published, self-contained artifact branch. Non-default-ref import, SDK-only/no-application-build deployment and the native model path have accepted C4 evidence. Permanent public publication is now authorized by the continuation below, but is not yet implemented or verified.

## Glossary

- **Decision_Bridge**: the browser-side adapter that previews a node, renders the frozen context, calls the decision Worker, validates the returned option and queues the trigger plus `Choose` inputs.
- **Decision_Worker**: the Cloudflare Worker route at `/api/decision` that calls the Workers AI binding. It has no simulation state.
- **Sim_Worker**: the browser Web Worker that owns the single `WasmSim`.
- **Decision_Node**: the existing underworld `dream_interpretation` or `magistrate_ruling` node.
- **NodeSpec**: the read-only preview result: family, predicted trigger sequence, Frozen_Context, closed options and Rules_Default.
- **Eligible_Node**: a supported node whose trigger passes preview with a legal closed set. Eligibility is distinct from readiness and budget to make a POST attempt.
- **Decision_Fingerprint**: a fixed-size digest identifying the provider, model, System One mapping version/hash and response schema for an accepted model choice.
- **Model_Choice**: the option ID returned by clef and accepted by local validation.
- **Rules_Fallback**: no model `Choose` input is submitted; the existing Rules_Default resolves the node.
- **Session_Cap**: the maximum number of model attempts for one page document; a JSON safe integer from 0 through 9007199254740991, default 40 only when the deployer setting is missing. It is not a server quota or abuse barrier.
- **Artifact_Branch**: the generated public Git branch containing only the prebuilt page, WASM, Worker module, Wrangler configuration and deploy metadata.
- **Artifact_Publisher**: the post-gates CI job that updates the Artifact_Branch without changing `main`.

## Requirements

### Requirement 1: Preserve the deterministic simulation seam

**User Story:** As the simulation author, I want the model outside the simulation, so that the game remains deterministic and playable without a network.

#### Acceptance Criteria

1. `sim-core` SHALL continue to compute every Decision_Node's facts, Frozen_Context, closed option set, effect bounds and Rules_Default without reading a clock, environment, network, thread or model.
2. The Decision_Bridge SHALL consume only a read-only NodeSpec and SHALL submit the model choice only as the existing `Choose` TickInput paired with its trigger input in the same tick.
3. A model error, timeout or unavailable Decision_Worker SHALL leave the simulation valid and SHALL resolve the node by the existing Rules_Default path.
4. Replaying a recorded input stream SHALL never contact the Decision_Worker and SHALL produce the same per-tick Checksums as the recorded run.
5. The native CLI, replay verifier and `sim-core` tests SHALL remain playable with no Worker URL, token, environment file or model dependency.

### Requirement 2: Expose the pure preview and validation seam

**User Story:** As the browser bridge author, I want the existing Rust seam exposed through WASM, so that the browser does not reimplement node legality or prompt rendering.

#### Acceptance Criteria

1. `WasmSim` SHALL expose a read-only `preview_node` operation that accepts the current-tick trigger payload and returns the NodeSpec as strict JSON, including family, predicted trigger sequence, Frozen_Context, option IDs, option definitions and Rules_Default.
2. `preview_node` SHALL be read-only with respect to the live `Sim`: clone-only deterministic keyed draws are allowed to compute the exact Rules_Default, but the operation SHALL not consume a live sequence, draw from live random state, change World state, change the input stream or enter the Checksum.
3. The browser adapter SHALL reuse the existing `sim-wasm` System One renderer and raw-choice validator, with their JSON envelopes distinguishing malformed input, render failure and an illegal option.
4. The production System One mapping SHALL match the pinned probe template byte for byte and be identified by version and SHA-256. Spec 7 SHALL keep `crates/sim-core/src/llm/`, its source-guard pins, and `eval/probe/templates/decision.system_one.v1.txt` unchanged.
5. A preview whose trigger would be rejected or would fire no node SHALL return a typed error and SHALL cause no model request.
6. Native and wasm32 tests SHALL compare the preview, renderer and validator JSON for the same input.

### Requirement 3: Build the Decision_Worker endpoint

**User Story:** As a deployer, I want a small same-origin Worker endpoint that calls Clef without exposing credentials to the browser.

#### Acceptance Criteria

1. The Worker SHALL serve the existing static assets, route `GET /api/decision/config` and `POST /api/decision` to its module, return fixed JSON 404s for the exact `/api` path and any other `/api/*` path, and preserve SPA fallback for non-API paths. The Wrangler route contract SHALL explicitly cover both `/api` and `/api/*`; API requests SHALL never fall through to assets. GET SHALL make no AI call and SHALL return the closed `decision-config-v1` DecisionConfig with readiness and a valid Session_Cap, or the versioned disabled error when an explicitly invalid cap prevents advertising a valid config.
2. The Wrangler configuration SHALL declare the native Workers AI binding `ai: { "binding": "AI" }`; the implementation SHALL call `env.AI.run("@cf/cloudflare/clef", request)` and SHALL not use a client-held token or direct Workers AI REST inference. This prohibition SHALL not exclude separately approved Wrangler control-plane authentication with an existing environment API token under Requirement 10.1. All corresponding Spec 7 Decision_Worker source/local, fake-AI runtime, C3/C4 and future hosted/artifact profiles SHALL explicitly use `compatibility_date: "2026-11-10"` with the existing pinned Wrangler/workerd and matching runtime compatibility flags; a test-only date downgrade SHALL not substitute for source-profile alignment.
3. `POST /api/decision` SHALL accept only the exact nine-key `decision-request-v1` Decision_Request: System One `state`, `instructions`, fixed `question_id`, `mapping_version`, `mapping_hash`, node family, exact bridge metadata and two to five option criteria. Unknown/missing fields at any level, duplicate criterion IDs, invalid bounded option-ID grammar, empty or over-bound decoded UTF-8 strings, excessive object/array depth and actual-body oversize SHALL be rejected before inference using the design's shared bounds and distinct 400/413 errors.
4. The Worker SHALL send exactly one Clef inference for one accepted request and SHALL not retry. It SHALL validate only the consumed native model/selected choice/usage projection, bound its strings/depth and check choice membership, discarding unconsumed provider members without REST unwrapping or probe tolerance. Only absent native usage SHALL project to required public `usage: null`; present usage SHALL be exactly the two allowed nonnegative safe-integer counters. Null, malformed, empty, partial, extra-key or out-of-domain present native usage SHALL be an invalid response, never unavailable usage. The Worker SHALL not return a raw prompt, raw response, probabilities or World snapshot.
5. HTTP 200 model success SHALL be the closed `clef-system-one-choice-v1` ModelDecision with the selected option, local pinned `@cf/cloudflare/clef` identity, mapping version/hash, C1-pinned Decision_Fingerprint, required canonical usage and required valid `session_cap`. Native model text SHALL be bounded and validated, not equated with or echoed as that public identity. The option SHALL belong to the request criteria. Public usage SHALL be exactly null or the exact two-counter safe-integer object; missing or partial public usage SHALL be invalid. POST cap SHALL be diagnostic only, never replacing cached GET cap or invalidating a valid result solely because the values differ.
6. All HTTP errors, including method/path errors, SHALL use the exact closed `decision-error-v1` DecisionError and the design's fixed kind/status pairings for malformed request, payload too large, model error, invalid response, disabled, confirmed quota, rate limiting, unavailable service and method/path errors. Public JSON responses SHALL use the design's JSON media type and no-store headers. The client SHALL validate success/error version, shape, literals, bounds, media type and HTTP pairing before classification; malformed, unsupported or oversized responses SHALL use local `invalid_response` fallback. Client-only network, timeout, session-cap, cancellation and manual statuses SHALL remain outside the HTTP enum; no error SHALL echo provider text, secrets, prompts or raw responses.
7. The Worker SHALL use same-origin routing in production. CORS SHALL not be required for the game path; any development-only cross-origin behavior SHALL be explicitly test-only.
8. Structured logs and traces, if enabled by the deployment configuration, SHALL contain outcome category, family, model, latency bucket and usage—not state text, synthetic person names or IDs, prompts, model output or credentials.

### Requirement 4: Validate and apply a model choice

**User Story:** As a player, I want an AI choice to be legal and replayable, not an untrusted mutation of the simulation.

#### Acceptance Criteria

1. The Decision_Bridge SHALL compare the returned Model_Choice with the preview's option IDs through the Rust validator before submitting it.
2. The bridge SHALL submit `[trigger payload, Choose { Trigger { seq: preview.trigger }, option, fingerprint }]` atomically through `submit_checked` only when both inputs are valid for the current tick.
3. If the shared strict public validator rejects the response, the server returns an option outside the preview, the mapping/fingerprint differs from the local pinned contract, or the Rust validator reports an error, the bridge SHALL submit the trigger alone and SHALL mark the node as Rules_Fallback. Invalid local request construction SHALL instead use checked trigger-only fallback with its malformed-request or payload-too-large reason, making no POST and spending no attempt; it SHALL not count as failed inference.
4. The bridge SHALL never submit a `Choose` created from an option list or default calculated in TypeScript.
5. The existing same-tick node resolution SHALL record `External` for an accepted model choice and SHALL record `Rules_Default` for a trigger-only fallback. Existing partial-effect and rejection rules remain unchanged. Fingerprint neutrality SHALL be tested separately from the fact that these sources are intentionally distinct checksum inputs.
6. A model result that arrives after timeout, world replacement or cancellation SHALL be ignored and SHALL not submit an input; the original operation SHALL still receive its one terminal protocol reply.

### Requirement 5: Enforce timeout and request budgets

**User Story:** As a deployer on the Free plan, I want bounded inference cost and predictable fallback behavior.

#### Acceptance Criteria

1. The browser SHALL count each inference attempt against the Session_Cap before sending it, including attempts that later time out or error. The counter SHALL persist across `create-world` operations and reset only when the page document is unloaded or reloaded.
2. The Decision_Bridge SHALL wait up to 10 seconds by default for one in-flight model request for the pending eligible node. The player MAY configure the page-session wait limit from 0 to 10 seconds. A 0-second setting SHALL skip model inference and use Rules_Fallback immediately; a non-zero setting SHALL stop waiting and use Rules_Fallback when its limit expires.
3. The browser SHALL make no retry after timeout, network error, HTTP error, invalid response or quota exhaustion.
4. The page document SHALL stop requesting when the cached GET Session_Cap is reached. The cap SHALL be a JSON safe integer from 0 through 9007199254740991; missing deployer setting defaults to 40, while explicit invalid values SHALL not coerce, clamp or default. Zero SHALL prevent every page inference attempt with `session_cap` fallback without itself disabling server readiness. Comparison and increment-before-dispatch SHALL remain safe at the maximum value; POST's required cap is diagnostic only. This cap SHALL NOT be represented as protection against direct public Worker calls.
5. The Worker SHALL require an explicitly set integer request-body cap in the supported range `1..=1048576` actual serialized UTF-8 bytes and reject over-cap bodies before inference, independently of Content-Length. 1048576 SHALL remain only a supported safety ceiling, not a default or selected cap. The Spec independently selects `16384` as the permanent project policy using accepted C3 and the 1,410-request offline corpus; implementation pin and boundary proof remain pending task 5.3. The sampled maximum is 12,239 bytes, leaving 4,145 bytes (33.87%) headroom, not worst-case coverage. Larger otherwise valid contexts SHALL use explicit HTTP 413 `payload_too_large` and checked Rules_Default fallback before AI; this policy SHALL NOT imply a <=50-neuron guarantee. Task 5.3 SHALL prove valid exact-16384-byte bodies make one fake-AI call only when explicitly enabled, and 16385-byte bodies make zero, including multibyte/escaped JSON and absent Content-Length. Missing/invalid configuration SHALL disable inference; no default or alias SHALL hide it. Ordinary source inference and candidate selection SHALL remain off; separately approved C4 temporary caps are not authorized by this pin and may differ.
6. The implementation SHALL record provider usage where supplied. Report the approximately 50-neuron target against actual provider data or a labeled estimate from an applicable documented rate; otherwise report it as unknown.
7. On a confirmed platform quota error, the bridge SHALL use Rules_Fallback and show a fixed daily-quota notice. A generic provider 429 SHALL use Rules_Fallback with a distinct `rate_limited` reason and no daily-quota notice. The implementation SHALL not create an application-owned daily counter.
8. Session-cap, payload-too-large, timeout, network, invalid-response, quota and rate-limited fallback SHALL each have a distinct reportable reason.

### Requirement 6: Record provenance without changing simulation facts

**User Story:** As a replay author, I want to know which model produced an accepted choice, while keeping the simulation checksum determined by the chosen option and World rules.

#### Acceptance Criteria

1. An accepted model `Choose` input SHALL carry a Decision_Fingerprint derived from the provider, model, mapping version/hash and response-schema version. The live bridge SHALL compare it with the locally expected digest; the replay reader checks format, not current model identity.
2. A Rules_Fallback SHALL carry no model fingerprint and SHALL use the existing no-external-choice resolution path.
3. The fingerprint SHALL be encoded in the replay input when present, omitted for existing no-fingerprint choices, and decoded with `deny_unknown_fields`.
4. Adding or changing a fingerprint SHALL not change the World canonical encoding or a per-tick Checksum for the same applied option and `ChoiceSource`.
5. Existing replay version-5 inputs without a fingerprint SHALL remain byte-identical after decode/encode. New model-bearing records SHALL round-trip byte-identically.
6. Replay verification SHALL not require network access, the Worker, the mapping file at runtime or a model license.
7. Tests SHALL prove that two runs with the same option and `ChoiceSource` but different fingerprints have equal World Checksums and distinct replay provenance; a model choice and trigger-only Rules_Default fallback remain separately tested because their sources differ.

### Requirement 7: Integrate the bridge into the Sim_Worker

**User Story:** As a player, I want a dream or ruling to use slow thinking without giving the browser a second simulation or allowing time to advance during the request.

#### Acceptance Criteria

1. The Sim_Worker SHALL own the only WasmSim and SHALL own the Decision_Bridge; the Main_Thread SHALL receive status and outcome notices but SHALL never construct a model request from simulation facts.
2. The existing Dream control SHALL invoke the bridge; the internal seam SHALL also accept Bribe without adding a Bribe control. Before inference dispatch the bridge SHALL preview the trigger and obtain a legal closed set; rejected preview makes no model call. Exactly one config-prefetch attempt per page document SHALL have an independent 3000 ms deadline beginning immediately before dispatch and covering headers, bounded response read, decode and strict validation. It SHALL abort on deadline/document disposal, never retry or reset on a partial response, and never block gameplay or depend on the decision wait preference. Unready, failed or disabled config, over budget or zero wait SHALL use checked trigger-only fallback immediately. Failure leaves inference unavailable until reload; late valid config affects only future operations. World replacement SHALL not abort/restart prefetch or reset config/cap/spent. Fakes SHALL use the same bound with injected clock/timers, not real multi-second sleeps.
3. The Sim_Worker SHALL lock tick advancement and competing inputs from before preview through terminal submission, including scheduled Frames and `run`, `step`, `pause`, `set-speed`, `choose`, Dream, claim, Carry_Over and raw `submit`. Read-only queries and changes to the wait preference for later operations MAY continue. A matching `Use rules now` commits only the checked trigger. Successful `create-world` instead cancels the operation before replacing the WasmSim without committing the trigger; failed creation leaves the old operation and World unchanged.
4. On model success, the bridge SHALL atomically queue `[trigger, Choose { Trigger { seq: preview.trigger }, option, fingerprint }]` in that order. On Rules_Fallback it SHALL queue only the trigger.
5. A successful model choice SHALL produce the same next tick and World checksum as direct checked submission of the corresponding trigger and option; a fallback SHALL produce the same next tick and checksum as the trigger alone.
6. A world replacement, page-session reset or Worker failure SHALL invalidate the in-flight operation; a late result SHALL not submit an input or change a checksum.
7. The page SHALL expose only the minimal model wait-limit and decision-status controls needed by this requirement; it SHALL not add a general settings page or change the B-direction layout.
8. The existing Spec 6 rules-only behavior SHALL remain playable when the Decision_Worker is unavailable or inference is disabled.
9. Only in the async decision window does this override FIFO reply order in WS-R2.7 and FP-R8.11: later requests MAY receive terminal replies ahead of the pending decision, matched by existing request IDs. Each request receives exactly one terminal reply while the Worker is live, including a cancellation reply for a superseded operation; a fatal Worker failure instead settles clients via the existing failure path. Same-World completion restores running pacing from a fresh anchor with no catch-up or leaves a paused World paused. The decision does not introduce a simulation stop reason.

### Requirement 8: Measure in-simulation behavior

**User Story:** As the author, I want evidence that a Clef choice can be applied in the real simulation and can be compared with what the rules would have chosen.

#### Acceptance Criteria

1. Decision_Metrics SHALL live outside the World Checksum and SHALL record eligible nodes, model request attempts, accepted choices, Rules_Fallbacks by reason, latency buckets, usage, selected option by family and agreement with Rules_Default.
2. Decision_Metrics SHALL never include prompt text, person names, full Frozen_Context, raw model output or credentials.
3. An offline native metrics command or test SHALL consume a read-only export of the actual browser run's v5 input stream, seed/config and checksum history, and compare each accepted option with the frozen Rules_Default and node family without calling a model. The export is an audit/test seam, not a player-facing replay UI. Family attribution SHALL use the recorded trigger sequence or deterministic replay reconstruction; it SHALL not infer a family from tick alone.
4. Metrics SHALL distinguish `dream_interpretation` and `magistrate_ruling`, model choices and Rules_Default resolutions; an absent inference result SHALL not be reported as a model failure. Request/error denominators SHALL come from explicit fake/error matrices or bounded telemetry, not from guessing failure causes from trigger-only replay inputs.
5. Acceptance SHALL include a real Workers AI choice applied and captured by the browser export, offline verification of that run, and a separate invalid-response/fallback trace (which MAY use fake AI). Gates SHALL never invoke live inference; if no separately approved live browser attempt succeeds, report the live criterion as unverified without substituting fake success or retrying on the same approval.
6. The selected project policy SHALL retain the accepted C3 request's 7,386 UTF-8 bytes, actual usage 2,544 input/0 output tokens and 888.711918 ms client-observed latency, plus the offline corpus's Dream 1,387 requests at 6,243–12,239 bytes and Magistrate 23 at 5,848–7,608 bytes. The corpus covers two lineages of one 50-resident seed-185 fixture with limited legal history, not all worlds or worst cases. Task 5.3 SHALL record the selected cap, sampled headroom and usage uncertainty without promoting the C3 temporary cap automatically or treating bytes as tokens/neurons. Separate reason-specific attempt/fallback denominators from fake matrices or bounded telemetry SHALL remain distinct from replay applied-option comparisons and the single live sample; that sample is not a rate. Clef remains the hosted default only after separately authorized rollout, with Rules_Default as fallback.
7. For this slice, the existing rule scores and personality priors SHALL continue to determine Rules_Default, and rules SHALL still determine the legal option set. Clef receives rendered fictional character facts, not those scores. Neither equal nor different choices establish personality quality.
