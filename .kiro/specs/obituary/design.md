## Architecture

1. The core captures a complete read-only own-death kin summary from World relationships at the death instant and delivers it with the completed death-day StoryBatch. A pure frontend projection freezes that life's identity, summary and supported event/choice facts, then constructs the exact fixed template.
2. In live authenticated judge mode, latch one narration attempt and use a dedicated judge route sharing the existing AI binding and admission pool. All other modes select the template locally. Neither path owns a simulation input, decision hold, clock or scene queue.
3. Store the selected terminal text; reveal it after the existing own-death performance settles, is skipped or is legitimately retired by the next scene. If generation finishes later, reveal later. Retain it with that historical life.
4. Export terminal text in a separate presentation sidecar bound to the unchanged existing replay-v5 export bytes. This Spec supplies no browser import, replay playback, archive viewer or gallery; external/future consumers can reuse the recorded text without another model request.

### Source facts that constrain the design

- `crates/sim-core/src/tick.rs` completes deaths/estates, funeral offerings and the remaining daily steps before `observations.rs` publishes the observed suffix. A whole admitted death-day batch is the trigger, not a partially received Death event or the next displayed calendar day.
- `story.rs` already exports frozen native `ageAtDeath`, actor names/origin, causal EventIDs, Chronicle results and oriented participant context. `LifeNotebook` retains them across rebirth; `EntryContext` binds each record to its actual life.
- Existing participant-only ActorContext is insufficient for an obituary family list. The Author now authorizes the dedicated read-only own-death summary below; survivors and precededInDeath are complete known arrays at every actual player death, not nullable guesses from a stale frontend World.
- `demand_payment` (`narrator/options.rs:238–244`) applies a quarrel, not repayment. Actual Repayment has the original Loan EventID in `causedBy` (`economy.rs:341–399`); partial repayments retain that identity.
- Inheritance amounts are **cash plus property valuation**. No-heir estates emit no Inheritance. Empty records cannot establish zero estate; per-recipient saturation cannot establish an uncapped pre-death total.
- Replay v5 rejects unknown fields. Keep the existing export and core replay machinery untouched; the separate hash-bound obituary sidecar is export-only in this Spec.

**Approved observation scope:** only the new death-time kin summary expands the factual projection. It changes neither World nor EventLog/rules/RNG/checksum/replay v5. No-heir or saturation-ambiguous estate valuation remains unavailable; kin lists do not. Empty complete arrays alone omit the family lines.

## Components and Interfaces

### 1. Read-only death-time kin summary and frozen fact projection

CoreFactsOwner extends the existing internal TickObserver with a default no-op successful-death callback receiving &World, the deceased PersonId and actual Death EventId. In death.rs invoke it **immediately after the Death append succeeds, before birth-slot/estate/debt/relation/Life/Soul cleanup**. Collector checks the deceased's immutable native soul against the player soul, not the potentially obsolete day-start Focus, and writes one summary into its own transient StoryCollector batch. No default observer scans/allocates family data for NPC deaths; no World/Sim member, canonical cache, new event or RNG draw is added. Existing replay closure observers inherit the default callback, so replay.rs is untouched.

Read directed outgoing World kin edges (what to is to from) and join immutable Persons for native name/sex/alive/death state. Living spouse is Spouse+Alive; earlier-dead spouses include retained Spouse **or** FormerSpouse+Dead. Death does not retag the old Spouse edge, and remarriage does not delete it: using FormerSpouse alone would omit Clifford. Living children/previously deceased children use Child; parents use Parent; grandchildren use Grandchild union Child→Child traversal. Siblings use direct Sibling union shared-parent Parent→Child traversal, excluding self. This read-only union avoids missing a sibling born after an older sibling died without inventing household/surname kin. Deduplicate/sort by PersonID per category; completeness refers to actual retained native relationships, not invented external genealogy.

Deaths settle in native ascending-ID order. At capture the dying body and later-settled same-day bodies are still Alive; lower-ID deaths already settled are Dead. Survivors therefore mean alive at this exact death instant; predecessors include deaths already settled on that day, not only deathTick<tick. Later-day births/marriages/deaths never relabel this summary. The full tick subsequently adds the ordinary Death/Inheritance/Offering facts and publishes them together with the summary.

The new observation-only field in existing StoryBatch version1 is ownDeathSummaries, omitted/empty when no actual own death occurs. Every newly observed actual own Death has exactly one matching complete summary, including all seven arrays even when empty. Old participant context is not a substitute; a missing matching summary is a producer/integration error to repair. Fresh opening/zero-tick history does not manufacture a summary for old deaths. Use the existing StoryBatch names/ID serializers; extend the read-only core/WASM/Worker/client/notebook transport together, not replay serialization.

Person/body use existing PersonID serialization; deathEvent/tick use existing canonical decimal strings. Render name with native FullName::text(sex); sex is the existing two-value native enum. For a traversal-derived sibling/grandchild, relation is an observation label supported by that actual parent/child path, never a persisted new kin tag. Validate category/relation, unique person per category and exact body/event/tick join; the same person may legitimately have multiple actual roles in different categories.

`web/src/main/obituary-facts.ts` accepts the admitted notebook, the exact own-death lifecycle/event **and matching complete summary**. It freezes model facts once per death using the summary's names/sex/roles and existing identity/choice/estate/offering evidence. Keep immutable life ownership and numeric precision; do not clone World or rerun projections on every Status. Store the summary as observation data in the existing factual notebook; it never becomes canonical simulation state or model transport metadata.

`web/src/main/obituary-template.ts` consumes the closed facts and the Author's [copy-deck section 14](../../../target/life-unfolds/copy-deck.md). Copy literal text into production constants; runtime does not read ignored target files. Select the exact native/borrowed/rebuilt opening, never drop it because of origin. Complete empty family lists omit their lines; unsupported non-kin facts omit whole lines without qualifiers. k=0 omits the offering line, k=1 uses its supplied singular sentence. Keep the final line unconditional and template line order/line breaks. The template is not subject to the model's 40-word minimum.

Lists group the same relation in stable native-person order, then render first names: `husband Marvin; son Marcus; grandsons Ben and Leo`. Use supported sex-specific relations; unknown sex uses spouse/parent/child/sibling/grandparent/grandchild. No `you`, parentheses, earlier-life qualifier or surname-based kin inference. Unknown names do not acquire an invented replacement biography.

## Data Models

The model sees this object and nothing else. All keys are closed at every nesting level. Decimals are canonical strings, not JS floating-point money/counts. `null` means unavailable; `[]`/`"0"` mean a complete known empty list/zero.

```ts
type Relation = 'husband' | 'wife' | 'spouse' | 'father' | 'mother' | 'parent'
  | 'son' | 'daughter' | 'child' | 'brother' | 'sister' | 'sibling'
  | 'grandfather' | 'grandmother' | 'grandparent'
  | 'grandson' | 'granddaughter' | 'grandchild';
type NamedRelative = { fullName: string; firstName: string; sex: NativeSex; relation: Relation };
interface ObituaryFactsV1 {
  version: 1;
  deceased: {
    fullName: string;
    sex: NativeSex; // existing deceased StoryActor/native identity, not inferred from name
    ageYears: number; // frozen native ageAtDeath, never current-body age
    deathDate: { year: string; day: number; label: string }; // existing 365-day calendar

  };
  survivors: NamedRelative[];
  precededInDeath: NamedRelative[];
  debtActions: { forgivenDebts: string | null; demandsMade: string | null; peopleAskedForPayment: string | null };
  collections: { debtsPaidOn: string | null };
  estate: { valueDollars: string; heirs: { fullName: string; relation: Relation | null }[] } | null;
  jossBurnersOnDeathDay: string;
}
```

Validate monetary/count decimals within u64; a distributed total beyond that representable factual domain is unavailable, not clamped. ageYears is an integer 0–120; day is 1–365, year is canonical positive decimal and label must equal the existing calendar output for those fields. fullName/firstName must have the existing native ASCII name form (two title-case words / their first word, at most 128 characters), not arbitrary instructions; firstName must match fullName. Validate nested relation/enums and each array entry's closed shape, reject unknown fields and oversize bodies without truncation. No numeric/date/name field is a free-form prompt channel.

Kin arrays are required and complete, with sex preserved from the native summary and male/female roles rendered accordingly. Unknown is still meaningful for unsupported non-kin aggregates/estate, never for a missing summary or mandatory deceased identity. Native kin uniqueness is by PersonID per category, rejecting repeated IDs within a category without deleting a person who has multiple recorded roles across categories. The model projection has no IDs: distinct actual people may produce identical fullName/relation entries in survivors, precededInDeath or estate.heirs. Retain every such entry, its actual name and stable native-ID-derived order; do not merge, rename or truncate people, or add IDs to model facts. Body sex comes from the existing native identity so She/He is factual, not guessed from a name.

Fact extraction rules:

- The date is the actual Death event tick, not the next-day Status tick. Name/native age/origin select one exact first line: born in town, borrowed body or rebuilt body. Do not omit or qualify the first line merely because the body was borrowed/rebuilt.
- Use the new death-time summary for complete surviving spouse/living children/grandchildren and predeceased spouses/parents/children/siblings. Preserve its name/sex and relationship labels; an actual empty array omits that family line. Missing summary on a real own-death delivery is an implementation defect, not permission to ship a familyless obituary or guess from frontend snapshots.
- `forgivenDebts`: count distinct original loans whose actual DebtForgiven records join to this life's selected `forgive_debt` Chronicle/appended evidence. Skipped part 0, automatic death forgiveness and earlier lives do not count. A selected option alone is not a successfully forgiven debt.
- `demandsMade` counts actual same-life non-skipped demand choices; `peopleAskedForPayment` counts their distinct actual target people. Neither is received money. `debtsPaidOn` counts distinct original loans with actual same-life repayment to this body, including partial repayments once. Missing causal evidence stays unavailable rather than becoming an invented collection.
- `estate`: exact BigInt sum of all Inheritance asset valuations caused by this Death and their actual beneficiaries. Do not substitute cash, subtract unrecorded liabilities, list merely eligible heirs or treat no events as zero. If saturation makes an uncapped estate claim uncertain, omit the estate object.
- `jossBurnersOnDeathDay`: distinct actual offerer IDs for this ghost on the Death tick, including positive burned amounts with zero credited amount. Other days, eligibility lists and funeral attendance do not count. A completed suffix with none establishes zero.
- Complete empty family arrays omit the corresponding lines. Use the joint debt sentence only when both supported counts are positive, otherwise the existing one-sided sentence for the supported positive count; unknown is not zero. No supported positive count omits line4. k=0 omits the whole offering line, k=1 uses One person, k>1 uses the supplied plural.
